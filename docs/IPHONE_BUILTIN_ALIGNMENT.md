## 3. 全部电台统一直连与旧取址代码删除：必须实施

### 3.1 身份和数据来源

保留 `builtin.kiss`、`builtin.music-radio`，以及名称、分类、频率、排序／隐藏和默认选择的兼容语义。内置身份只限制管理权限和标识资料来源，播放流程不再为内置台分派动态取址；iPhone 本身不提供任何电台编辑入口。

正式 iPhone App 从本包解密后的内置资料取得 `urls`，普通台继续来自默认 JSON 或已采用的同步缓存。所有台使用同一固定列表规则：`max(0, sourceAttempt) % urls.count`；空列表明确失败，不能越界、偷偷删台或回退动态取址。

构建输入沿用 Mac 已确认的完整地址；本机路径为 Mac 仓库中被 Git 忽略的 `private/builtin-streams.json`，也支持成对环境变量 `KISS_STREAM_URL`、`CNR_STREAM_URL`。只在本机受保护的构建环节使用，禁止把真实值复制到需求文档、聊天、源码、夹具、日志或公开提交。

不要猜测备用地址、改用其他服务或恢复旧取址接口。当前两台各一条线路，单线路失败重试原地址；完整保留路径与查询参数，不解码重写，不将 expires/time 等参数解释为刷新期限。

### 3.3 重试、文案与网络约束

沿用四次自动重试、2/4/8/16 秒退避，含首次最多五次连接；线路位置与重试预算独立，连续健康播放超过 60 秒后重置预算，不重置线路位置，下次失败继续下一条，不能强行切回主线。中途停止推进则重新计算连续健康时段。保持 25 秒无进展处理；地址多于五条时不能承诺一次失败会遍历全部地址。

生产文案使用固定线路的连接、缓冲、重试状态，不再显示“动态取址”“TingFM 签名验证”或“刷新直播地址”。中英文同步，繁体沿用转换。正常 HLS 播放列表与分片的更新继续由 AVPlayer 负责，不得把“删除动态取址”误解为禁止播放器正常网络请求。

ATS 只保留实际需要的主机例外。旧取址专属例外在确认无使用后移除；真实媒体链路仍按 iOS 系统网络规则验证，不能全局放开 ATS。

诊断继续只在内存保留最多 100 条事件／64 KiB 文本，不记录完整地址、token、请求头或响应正文。固定源错误可报告线路索引及错误类别，不借清理旧诊断新增持续日志系统。

## 5. iCloud 与内置台的边界

**内置地址不会经现有 iCloud 协议同步到手机。** `current.json` 的普通电台文档不包含这两个内置台地址；它们的排序、显示和默认选择通过稳定 ID 在共享偏好中引用。iPhone 必须自行打包地址资源；以后仅更新内置地址需要相应 iPhone 构建，单独刷新云端配置不会替换包内地址。

继续使用既有 v2 文件、字段、序号和大小限制，不修改 wire schema，不把内置台伪装成普通台，也不把明文内置地址、密钥或密文资源塞入共享文档。

- 合法的普通台空数组仍与本地两个内置台合并；文件缺失／损坏不是有效空配置。资源不可用时仍保留内置身份和偏好，不清空有效缓存。
- 内置台隐藏／排序／固定默认的同步与普通台遵循同一规范化规则；至少一个显示台。手机不擅自显示 Mac 隐藏的台，也不重新生成 ID。
- 保留同库序号递增、同序同内容不重复采用、旧序忽略、同序异内容拒绝、异库明确确认、缓存先持久化后发布，以及解除／换源的代次门控。
- 名称、排序、显示、地址或默认模式变化不得中断健康播放。已开始的一次连接尝试使用自己的 Station 快照；下一次手动重连、重新选择或自动重试重新取得同 ID 的最新有效配置，不在同一次尝试中混用新旧地址。若电台已被删除，旧会话的自动恢复仍可沿用其原快照；从后续可选集合移除，不因删除立刻停播或自动切台。这与 Mac 当前 RadioPlayer 每次重试重新读取有效资料的边界一致。
- 配置消费不能创建播放请求、激活音频会话或解除来电／输出变化的安全锁。音量、语言、上次收听、自动播放意图等设备状态继续留在本机。
- 本轮不重置来源书签、库标识、已接受序号门槛、当前／上一份有效缓存或已有偏好。升级和重新签名使用覆盖安装方式验证，不能靠删除 App／清空缓存绕过兼容问题。

v2 字段与采用细则参考 [两端协议](IPHONE_SYNC_SIMPLIFICATION.md) 的协议部分，并核对当前 [StationSync.swift](../Sources/RadioBar/StationSync.swift) 与手机读取器。该旧文档中的“动态取址由手机负责”“保留 8 秒切台”以及“当前版本 1.2.14”已过时：本轮分别由本文第 3／6 节和当前 HANDOFF 覆盖；其有效 v2 格式不因此变更。iPhone 目录的 `IPHONE_CURRENT_V2.md` 也有这些旧说明，实施时一并订正相关记录。

## 6. 切台对齐与 iPhone 安全保护

移植 Mac 2.0.1 起的分段过渡：新台先静音连接，只有 ready、playing 且时间推进后才开始交接；旧台 0.8 秒淡出，两路静音至少 0.5 秒，新台 1.2 秒淡入。各段沿用 smoothstep 与现有正弦／余弦增益曲线，不同时输出两台声音。2.5 秒不含网络连接／缓冲；计时回调延迟不能跳过静音间隔。

具体曲线与时序沿用当前 Mac：每段 `s=p²(3−2p)`；淡出为旧台起始 gain × `cos(πs/2)`、新台 gain=0；静音从回调实际将旧台归零时计满 0.5 秒；淡入时旧台 gain=0、新台 gain=`sin(πs/2)`。实际写音量时先将另一台归零，再提高当前台，不能只在最终状态断言中做到不叠音。过渡中新台停滞／缓冲时取消过渡、将新台归零并恢复仍可播放的旧台；失败时沿用旧台回退。若旧台已经不可播放，沿用 Mac 清理旧实例并正常播放新台的分支，不制造虚假的旧台回退。

保留最多两路、新台失败时旧台仍可播放、快速切台和暂停取消、睡眠渐弱 6 秒、独立静音以及最终新台 gain=1。静音间隔内快速切台时，按 Mac 现行实现保留已经确认时间推进的新台，避免“双方 gain=0”错误丢弃有效播放。

静音不得写零覆盖已保存音量，过渡完成的 gain=1 不得绕过静音门控；不增加增益补偿或响度归一化。保留既有睡眠逻辑及取消保护，不为对齐共享代码新增手机睡眠设置入口。

**不要直接覆盖整个 RadioPlayer／SleepTimer／AppLanguage 文件。** iPhone 已有 Mac 当前源码不具备的平台适配与衔接，必须保留：
