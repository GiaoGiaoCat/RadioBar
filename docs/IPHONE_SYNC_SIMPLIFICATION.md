# RadioBar 单向配置发布：给 Dot 的 iPhone 整改需求

日期：2026-10-22。状态：已先行交给 Dot 的两端约定；Mac 自 1.2.10（99）起按本文完成本地实现、回归、构建及 ZIP 验签，当前正式发布版本为 1.2.14（103）；真实双端 iCloud 待联调，交付状态见 [HANDOFF](HANDOFF.md) 与 [TESTING](TESTING.md)。Mac 1.2.9（98）及更早版本仍输出旧格式。

本文取代 [旧 iPhone 需求](IPHONE_REQUIREMENTS.md) 中的版本图、分支、同步排查及历史读取方案；播放器、稳定电台 ID、设备偏好和原生目录授权约束继续适用。两端以本文的 v2 文件约定联调，旧实现只作迁移参考。

## 1. 目标与分工

- 只有一台 Mac 管理电台，负责添加、编辑、删除、排序、显示选择及默认电台模式，并自动发布完整配置。
- iPhone 只读取配置和收听，不编辑、不上传、不合并、不创建云端版本，不删除共享文件。
- 使用用户授权的 iCloud Drive 文件夹；不增加服务器、CloudKit、账户系统或后台保活。
- 优先减少代码和界面。不要为本次需求新增通用同步框架、版本图、所有权选举、订阅或诊断平台。
- 在现有 iPhone 工程中修改，先检查实际源码、Git 状态和工程内 AGENTS，保留未提交改动。不要覆盖整个工程，不重做现有播放器和首页。

## 2. 预期 Mac 成果

Mac 1.2.10 按下列范围实施，实际验证边界见 TESTING：

1. Application Support 中的本机配置继续作为管理来源，成功保存的修改自动发布；离线或发布失败不回滚本机编辑。
2. 同步目录只更新一个 `current.json`，不再为每次修改新增 UUID 快照，不从云端自动应用配置到 Mac。
3. 保留设置／更改文件夹、立即同步、停止同步、简单状态和错误反馈；删除多 Mac 冲突比较、来源版本选择、占用统计、历史恢复及独立排查界面。
4. 保留配置校验、外部修改检测、备份及原子写入。新版自动备份固定保留最近 5 次，不提供数量／天数设置；只在配置保存成功且安全备份完整后轮替新版自有备份，失败恢复材料不参与清理。
5. 已有旧备份和云端 UUID 历史保留，不自动批量删除。iPhone 不负责清理它们。
6. 本地 JSON、稳定电台 ID、现有 UserDefaults 键和 bundle ID 保持兼容。停止同步保留本机配置、备份和云端文件。

## 3. 固定的 v2 文件约定

### 3.1 目录与文件

- 专用数据目录仍叫 `RadioBarSync`。Mac 常用位置仍为 `iCloud Drive/RadioBar/RadioBarSync/`，已有根目录下的 `RadioBarSync/` 也可继续使用。
- iPhone 接受用户明确选择的数据目录，或其直接父目录；仅检查这两种位置，不递归搜索，不重复嵌套，不硬编码 Mac 路径。
- 新协议唯一入口为 `RadioBarSync/current.json`，UTF-8 JSON，最大 **4 MiB**。
- 忽略旧版 `<UUID>.json`、其他文件、子目录及程序临时文件，不再枚举和解析整个版本历史。
- `.current.json.icloud` 是系统下载占位，不是配置。只报告等待／请求系统下载，不读占位正文，不创建替代文件。
- 目录／文件缺失、权限错误、符号链接和未下载均不能被当成有效空配置。

### 3.2 文件结构

可直接使用的夹具见 [station-current-v2.json](examples/station-current-v2.json)。这是格式示例，不是真实云端配置：

```json
{
  "schemaVersion": 2,
  "libraryID": "aaaaaaaa-aaaa-4aaa-8aaa-aaaaaaaaaaaa",
  "sequence": 1,
  "publishedAt": 1792627200,
  "configuration": {
    "document": "eyJzY2hlbWFWZXJzaW9uIjoxLCJzdGF0aW9ucyI6W119",
    "preferences": {
      "orderIDs": ["builtin.kiss", "builtin.music-radio"],
      "visibilityOverrides": {}
    }
  }
}
```

| 字段 | 必须遵守的含义 |
|---|---|
| `schemaVersion` | 整数，固定为 `2`。与内层电台文档的版本独立；未知版本保留缓存，提示升级／等待兼容版本 |
| `libraryID` | 合法 UUID 字符串，表示配置库；比较 UUID 值，不依赖大小写。不得使用目录名、Apple 账户或修改时间代替 |
| `sequence` | 1～9,007,199,254,740,991 的整数，同一库每次内容变化递增；重复发布同一版本不递增、不改变内容。禁止布尔值、小数及越界值 |
| `publishedAt` | 有限、非负的 Unix 秒数，可含小数；仅展示，不用于判断新旧。**不是旧协议的 Swift reference-date 编码** |
| `configuration.document` | 标准 base64 字符串，解码为原始 `stations.json` UTF-8 字节，最大 **1 MiB**；保留未知 JSON 字段及原始地址值 |
| `configuration.preferences.orderIDs` | 稳定电台 ID 数组，不重复，沿用共享校验，上限 10,000 项 |
| `configuration.preferences.visibilityOverrides` | ID → Bool 映射，沿用共享校验，上限 10,000 项 |
| `configuration.preferences.defaultStation` | 可省略或 `null`：上次收听；`"random"`：随机；其他值：固定电台 ID |

示例的 `document` 解码为 `{"schemaVersion":1,"stations":[]}`。普通台为空仍有两个本地代码内置台；**它不同于文件不存在或读取失败**。

`configuration` 的结构沿用现有 `SharedStationConfiguration`／`StationDocument`／`SharedStationPreferences`，不新增第二套电台字段。内层文档继续为 `schemaVersion: 1`，最多 500 个普通电台；名称、地址、ID 及其他字段的校验沿用现有生产实现。

v2 不包含 `revisionID`、`parentRevisionIDs`、发布设备 ID 或分支信息。手机无需移植 Mac 的发布控制器、旧版本图、同步规划器或本机写事务。

### 3.3 发布与读取保证

- Mac 用文件协调和原子替换发布完整文件；完整快照同时包含电台资料及共享偏好，手机不拼接多份文件。
- Mac 持久保存已分配的发布序号及重试所需信息，重启／发布重试不能把同一序号用于另一份内容。重新关联同一库也不能静默重置序号。
- 单 Mac 是使用边界，不实现跨设备锁。如果发现共享文件被意外改写，Mac 应停止自动覆盖并提示处理。
- 文件提供商可能延迟、返回旧内容或暂时不可用。手机每次都完整校验，不能把本机文件写入成功当成对端已收到。
- Mac 无法恢复某库的有效序号时，应通过明确的新库／重新设置流程处理，不能在原 `libraryID` 下从 1 重新开始。

## 4. iPhone 的采用规则

| 已有状态／读到的文件 | 行为 |
|---|---|
| 没有 v2 缓存，首次读到合法文件 | 完整验证，持久保存来源及缓存，成功后绑定 `libraryID` 并发布列表 |
| 同库，序号大于缓存 | 完整验证并安全保存后，一次性采用新列表及共享偏好 |
| 同库，序号等于缓存且快照内容相同 | 无变化；不重写缓存，不触发播放器更新 |
| 同库，序号小于缓存 | 忽略旧内容，保留缓存；不提供“采用旧版本”按钮 |
| 同库，同序号但快照内容不同 | 报告异常并保留缓存，不能悄悄选择其中一份 |
| 不同 `libraryID` | 不自动切换；用户主动更改来源后，展示简短提示并确认，成功持久化后才切换 |
| 缺失、未下载、损坏、超限、较新格式或缓存写入失败 | 保留当前来源、缓存、偏好和播放；提供重试或重新选择 |

“内容相同”比较解码后的快照字段和完整配置，不因外层 JSON 排版／键顺序变化报错；电台文档沿用现有语义比较规则，未知字段变化也属于内容变化。

读取时在有效安全作用域内协调读取，拒绝符号链接，读取前及读取过程中限制文件大小。不能只检查文件名／修改时间，不能先更新界面后补写缓存。

新的配置通过现有共享偏好规范化规则：保留稳定 ID，至少一个显示台，固定默认台不存在或隐藏时回退。内置台继续为 `builtin.kiss`、`builtin.music-radio`，动态取址由手机现有实现负责，不从云端接收运行时 token。

## 5. 缓存、授权与读取节奏

- 继续使用 iOS 系统文件夹选择器及手机自己的私有书签，每次访问保持安全作用域有效。Mac 书签不能复制到手机。
- 在 App 私有持久目录保存完整已验证配置及库／序号，不使用可被系统随时清理的临时目录作为唯一副本。
- 只保留当前有效缓存和一份上一份有效副本，不积累历史，不增加缓存管理界面。当前副本损坏时可以使用有效上一份；同库防回退采用能恢复的最高已接受序号，不因为使用旧副本而降低读取门槛；若该门槛也无法恢复，提示重新选择来源，不能宣称已经验证新旧关系。
- 来源与缓存必须一致提交。更换目录失败／取消时保留旧来源和缓存；已绑定的库发生变化不能仅因路径相同就自动接受。
- 启动先使用有效缓存，再后台读取；回到前台及用户手动刷新时检查，合并连续目录变化通知。先不增加定时轮询、后台定时或后台保活。
- 解除关联停止后续读取，保留缓存和播放，不删除云端文件，不自动重新连接，不捆绑清空缓存。
- 取消、切换来源或解除关联后，旧任务不得提交结果；用来源和任务代次检查阻止迟到结果。
- 缓存只解决电台列表离线可用，直播音频仍需网络。

## 6. iPhone 最少界面与删除范围

在现有设置页保留一张“电台配置 / Station configuration”卡片，沿用现有视觉：

- 未设置时：选择同步文件夹。
- 已设置时：来源、最近成功采用时间、重新读取、更改文件夹、解除关联。
- 需要等待／失败时：一条简短原因和适用的重试／重新选择入口。无更新的成功读取可以只更新最近检查时间，不必常驻成功提示。
- 区分“最近检查”与“最近采用更新”，不显示“实时同步”“已上传”“Mac 已收到”等无证据状态。

不保留／不新增：历史列表、版本差异、回退、冲突处理、存储统计、清理策略、独立排查 sheet、同步诊断预览／复制／清除、分享／导入预留框架。已有播放诊断不属于本次删除范围。

仅供错误反馈的必要分类可以留在读取层，不为此新建诊断系统。错误不回显地址、token、书签或配置正文。界面简体中文／英文同步，繁体沿用现有转换，中文称“电台”，英文用 Station / Stations。

## 7. 旧版迁移和两端上线顺序

1. Dot 可以先用本文夹具开发；真实 Mac v2 输出需等 Mac 端交付后联调。夹具通过不等于 iCloud 真机通过。
2. Mac 升级时以已接受的本机配置为准，保留旧配置、备份、未完成事务及旧关联恢复材料；不能通过忽略旧事务来绕过恢复保护。新协议在原数据目录发布 `current.json`，不将旧云端分支导入本机，不自动删除旧 UUID 文件。
3. 如果可以可靠沿用既有关联的库标识，Mac 保持 `libraryID`；否则通过明确重新设置建立新库，不能静默混用。旧 UUID 文件不决定新协议的 `sequence`。
4. iPhone 只读取 v2 `current.json`，不为旧历史增加兼容扫描器。只有旧 UUID 文件时，提示“请在 Mac 更新并发布配置 / Update RadioBar on Mac and publish the configuration”。
5. 若 iPhone 已有旧版有效本地缓存，升级后先继续使用它；首次采用 v2 时验证有效来源及库标识，同库可迁移，异库明确确认。旧缓存无 v2 序号，不能伪造为 `sequence: 1`；首次 v2 缓存持久化成功后才结束迁移。
6. 旧缓存／旧授权格式若当前生产版根本没有实现，无需为历史规划补写迁移器。以实际代码和用户已有数据为准。
7. 协议字段、文件名或时间编码如需修改，应先更新本文并协调另一端，不在单端自行替换。

## 8. 必须保留的播放行为

配置读取层不能创建播放器、启用音频会话、自动播放、解除来电／输出断开安全锁或自动切台。

- 名称、顺序、显示和默认模式变化只更新资料及后续选择。
- 当前电台被隐藏／删除，保留正在播放的 Station 快照及健康连接，从后续可选集合移除。
- 地址变化不重建健康连接；下一次明确新建连接使用最新有效配置，已经开始的连接任务继续使用其快照，不混用新旧地址。
- 读取失败、断网、解除关联不打断播放；原播放器继续负责实际音频故障和重试。
- 保留最多两路、8 秒切台、6 秒睡眠渐弱、两路静音、快速切台／取消门控，以及现有后台音频和锁屏控制。

## 9. Dot 的验收清单

按 iPhone 工程现有脚本验证，至少覆盖：

1. 示例及真实配置解码，普通台空列表、排序／显示／默认模式、未知字段与带查询参数的地址保持。
2. 同库新序号、重复读取、旧序号和同序号不同内容；外层排版变化不能误报冲突。
3. 文件缺失、占位、未下载、损坏、格式过新、超限、链接及权限失效均保留旧配置。
4. 缓存写入失败、重启恢复、更换来源取消／失败、异库确认、解除关联和迟到结果门控。
5. 验证读取前后共享目录字节和文件列表不变，不创建 UUID 版本，不修改 `current.json`。
6. 配置更新和失败场景均不额外 load／pause，不自动播放；隐藏／删除当前台、地址变化及手机安全锁分别验证。
7. 简繁中文／英文、浅深色、大字号、滚动及 VoiceOver；沿用现有设置界面，不重做播放首页。
8. 使用实际签名 iPhone 验证 Mac 发布 → iCloud 到达 → 手机采用，以及断网重启缓存可用、恢复网络后更新。单独记录实际设备与限制。

完成时报告改动、当前源码构建结果、逻辑／界面／真机各自验证范围和待验收项。不要安装、推送或发布超出用户授权的产物，也不要以模拟文件读取代替双端真机验收。
