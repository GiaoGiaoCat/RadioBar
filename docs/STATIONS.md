# 电台 JSON 配置

2.0 基线中，KISS 和央广 Music Radio 是内置电台，只能隐藏、排序，不能通过用户 JSON 修改或删除。地址在构建时注入 App 资源（见 [README](../README.md#从源码编译)），运行时不读取私有构建文件；沿用 1.x 稳定 ID、用户 JSON 和同步格式。普通电台由用户 JSON 管理。

## 文件位置与生效方式

首次运行此版本，App 将默认的 10 个普通电台复制到：

```text
~/Library/Application Support/local.victor.RadioBar/stations.json
```

在设置的“电台配置”页点击“打开配置文件夹”，即可在 Finder 打开此目录，用纯文本编辑器修改 `stations.json` 并保存。也可使用 Finder 的“前往 → 前往文件夹”（⇧⌘G）打开上述路径。**保存后点击“重新加载”即可立即生效**，也可退出后重启；当前没有自动监听。请勿同时运行多个版本编辑配置。设置同时提供“打开配置文件”，通过默认编辑器直接打开已有的 `stations.json`；文件缺失时只提示，不创建空文件。

App 更新不覆盖已有用户文件，也不会补回你删除的普通电台。只有文件不存在时才重新创建默认文件。

需要恢复默认时，在电台配置底部点击“恢复内置电台列表”。App 先将当前文件原样备份为同目录中的 `stations.backup-pending-UUID.json`，再用本版 App 内置 JSON 完整覆盖 `stations.json`；备份失败则不覆盖，恢复失败仍保留已生成的备份。成功提示约 5 秒、失败提示约 8 秒后自动消失。文件不存在时无法备份，会停止恢复；下次启动会按首次运行规则创建默认文件。

**备份、覆盖成功后立即应用内置列表，无需重启**；当前播放不受影响，排序与显示偏好保留。此操作仅恢复 JSON，不等同于顶部的“恢复默认顺序”。

完整示例是仓库的 [stations.default.json](../Sources/RadioBar/Resources/stations.default.json)，随 App 打包。不要直接修改 App 包内资源，否则会破坏签名。

## 手动重新加载

“重新加载”只读取已保存的文件，不写回配置或自动创建缺失文件。完整校验成功后一次性应用；读取、体积或任何字段校验失败，都保留当前列表、偏好及播放，提示脱敏原因。语义内容未变化时提示“配置未变化”，不重建播放会话。成功提示约 5 秒、失败提示约 8 秒后消失。

- 同 ID 的名称、频率、分类立即刷新，播放连接继续；当前地址变更在下一次手动重连、重新选择或后续自动重试时使用。已经开始的连接使用其原快照，不能被新配置混用。
- 正在播放的电台被删除时，菜单显示移除提示，当前连接继续；切换后不能再次从列表选择。暂停后重新播放或手动重连会使用当前首个可见台。原会话中的自动重试仍可沿用被移除台的快照。
- 排序保留已有 ID 的位置，新 ID 追加。被移除 ID 的排序和显示记录保留但不参与当前列表，同 ID 重新加入时可恢复。主动“恢复默认顺序”仍清除自定义排序记录。
- 用户明确显示/隐藏选择优先于 `defaultVisible`；至少保留一个可见台。固定默认台被删除或隐藏时回到“上次收听的电台”；上次收听引用失效时，下次启动使用当前首个可见台。随机模式不立即重抽或切台。
- 加载、恢复互斥，文件处理期间禁止排序和显示操作；拖动排序期间不能加载或恢复。静音、音量、睡眠倒计时及正在进行的切台过渡保持原规则。

重新加载不进行网络探测，合法的 URL 不等同于电台能播放。已提供界面添加、编辑和删除；尚无自动监听、导入导出或逐台试播。

## 本地安全备份

编辑／删除／恢复内置列表前原样备份 JSON。新版备份先以 `stations.backup-pending-UUID.json` 保存，配置替换成功后将可校验的备份标为 `stations.backup-v2-UUID.json`，固定保留最近 5 次成功操作前的电台资料。没有数量、天数、统计、清理、历史或应用内恢复界面；“电台配置 → 打开文件夹”可检查文件，恢复需手动替换 JSON 后重新加载。

写入失败、无效原文件及未完成恢复材料不参与轮替。旧版编辑／重置／同步配对备份、未知命名、损坏文件和链接保留；有旧事务恢复记录时暂停轮替。备份失败不替换原文件，清理失败只保留更多旧文件，不影响已成功保存的配置。备份是电台 JSON，音量、上次收听等设备偏好仍保存在本机。

## 在设置中管理电台

列表卡片底部右侧的“添加电台”创建普通台；普通电台行的铅笔按钮打开编辑窗口，提供中英文名称、可选中英文全称、分类、频率，以及每行一个的主备地址。中英文名称都必填；可选双语字段要么都留空，要么同时填写。窗口内“删除电台…”需要确认；取消不写文件。两个代码内置台没有编辑和删除入口。列表较长时，向下滚动可找到添加、配置文件与恢复入口。

添加自动生成 `user.<小写UUID>`，编辑保留 ID 和未修改字段（包括 `defaultVisible` 与未知 JSON 字段）。界面不直接编辑 ID、默认显示值或 JSON 数组顺序；显示与排序仍使用现有列表控件和本机偏好。

新增或修改字段时，保存前清理首尾空白、零宽空格、BOM、word joiner 等隐藏噪声；名称内部正常空格不折叠，emoji 的变体选择符不误删，纯不可见输入视为空值。必填名称清理后为空会提示，可选双语字段均为空则省略。未修改字段及未知字段仍保留，不批量清洗旧文件。

网址按行处理，兼容 LF/CRLF，清理每行首尾后忽略空白行与仅含隐藏噪声的行；第一个有效地址仍是主线路。网址内部包含空格、控制符、零宽字符、方向控制符或其它默认不可见字符时，拒绝保存并提示输入中的原始行号（包括空行），不回显地址。不会拼接断开的地址、解码百分号或重写签名查询参数；已有未修改网址保留原 JSON 表示。没有有效地址仍校验失败，不生成备份或写入文件。

保存/删除先完整校验，再将原 JSON 字节备份为同文件夹的 `stations.backup-pending-UUID.json`，最后原子替换同一个 `stations.json` 并立即应用。备份或写入失败保留当前列表、偏好及原文件，已生成的备份保留。编辑窗口显示错误，内容不丢失，可修正再保存；成功结果自动消失。

打开窗口时读取已保存的 JSON 快照，保存前通过 NSFileCoordinator 协调并比较原始字节；检测到外部修改时不覆盖，需取消并重新加载后打开编辑。对不参与文件协调的外部编辑器无法提供跨进程绝对锁定，应避免同时写入。无效、缺失或符号链接文件不由界面自动替换，先修复或直接编辑原文件再重新加载。成功写入后仅轮替新版完整备份，固定保留最近 5 次；旧版及失败恢复材料不自动清理。

删除或编辑播放中的电台沿用上面的手动加载规则：现有连接继续、新地址用于后续连接、默认失效时回退，潜在排序/隐藏引用保留，始终至少有一个显示台。保存不是联网验证或试播。

## 最小示例

```json
{
  "schemaVersion": 1,
  "stations": [
    {
      "id": "custom.example.music",
      "name": {
        "zh": "我的音乐电台",
        "en": "My Music Station"
      },
      "defaultVisible": false,
      "urls": [
        "https://example.com/live.mp3"
      ]
    }
  ]
}
```

示例域名只是占位符，需换成真实直播源。`stations` 是普通电台的完整列表；用这个示例替换文件会移除原 10 台，只留下这一台和两个代码内置台。增加电台时，在原数组中追加对象即可。标准 JSON 不支持注释或末尾多余的逗号。

| 字段 | 必填 | 含义 |
|---|---|---|
| `schemaVersion` | 是 | 当前固定为数字 `1` |
| `stations` | 是 | 普通电台数组，允许空数组，最多 500 项 |
| `id` | 是 | 永久身份，文件内唯一；改名、换地址或排序时不要修改它 |
| `name` | 是 | 菜单和状态提示的名称，必须包含 `zh`、`en` 两个非空字符串 |
| `urls` | 是 | 1–20 个 HTTP/HTTPS 播放地址；第一项主线路，其余按顺序作为备用 |
| `defaultVisible` | 否 | 布尔值，缺省为 `true`；没有用户显示偏好时的初始值，`false` 表示默认隐藏 |
| `frequencyMHz` | 否 | 数字字符串，例如 `"99.3"`，不包含 FM/MHz；没有频率时省略 |
| `category` | 否 | 中英文分类对象，例如 `{"zh":"音乐 · 爵士","en":"Music · Jazz"}`；省略显示“自定义电台 / Custom station” |
| `fullName` | 否 | 中英文完整名称，用于悬停提示和默认电台选项；省略直接使用 `name`，频率由 App 拼接 |

繁体中文由 `zh` 的简体内容按现有逻辑转换。名称、完整名称和分类的每种语言最多 200 字，不能含换行等控制字符；整个文件不能超过 1 MiB。

## ID 约定

- `builtin.kiss` 和 `builtin.music-radio` 是两个内置台，整个 `builtin.` 前缀保留，不能写入用户 JSON。
- 新 ID 使用小写英文字母、数字、点和短横线，最长 128 字节。点或短横线之间都必须有字母/数字，不能有空格、下划线或中文。
- 人工添加建议使用 `custom.<自选分组>.<电台名称>`，如 `custom.victor.beijing-music`。分组能降低共享配置时的冲突概率，加载时仍会拒绝重复 ID。
- `user.<UUID>` 用于界面添加时自动生成的 ID，UUID 为小写，编辑时不改变 ID。
- 原有 10 台保持 `bcc`、`ufo`、`asiaFM`、`guangdong`、`shanghai`、`loveRadio`、`classic947`、`radioParadise`、`grooveSalad`、`swissJazz`，其中大小写形式是兼容特例。
- 旧内置 ID `kiss`、`musicRadio` 和默认模式 `random` 也不能用于普通电台。

首次升级自动把偏好中的旧内置 ID 迁移到新 ID，保留上次收听、固定默认、排序和隐藏记录。改名不会改变身份；更改 ID 则视作删除旧电台、添加新电台。

## 默认显示与用户选择

`defaultVisible` 从 1.0.66 开始支持，是 JSON 布尔值 `true` / `false`，不要加引号。上述最小示例的普通台默认隐藏，可在设置页开启显示。省略此字段与旧配置兼容，默认显示。

显示优先级为：设置页明确选择 → 旧版本保存的隐藏记录 → JSON 的 `defaultVisible`。用户主动显示一个默认隐藏的台后，即使 JSON 仍为 false，重启也保持显示；用户主动隐藏一个台后，JSON 改为 true 也不会将它重新显示。没有用户选择的台，修改 JSON 默认值后重新加载或重启会跟随新值。

设置中的选择保存到本机偏好，不写回 JSON，因此分享文件只分享默认显示值，不会分享个人隐藏偏好。恢复默认顺序仅调整排序，不清除显示选择。无论配置与偏好如何组合，仍保证至少一个电台显示。

设置页不再常驻展示显示规则，也没有单独的规则折叠入口。尝试隐藏最后一个显示台时，会弹出提示并保留该台；隐藏固定默认台时，会提示启动选择已调整。普通显示或隐藏操作不弹出规则说明。简短使用规则集中在 [README](../README.md#电台使用规则)。

## 地址、顺序与异常

- 所有电台统一使用有序固定 `urls`，第一个为主线路，其余为备用，按 `max(0, sourceAttempt) % urls.count` 选择。KISS 使用用户确认的固定转播地址，央广 Music Radio 保留原固定 HLS 主线路；两台当前各一条，没有动态取址或动态备用。内置身份仅限制编辑和删除，仍可隐藏、排序。
- 地址应直接指向音频流或播放列表，不能填普通收听网页。配置校验只检查格式，不验证联网、解码或实际出声。
- 请优先使用 HTTPS。HTTP 是否允许取决于 App 现有的 ATS 主机例外；新增主机不会自动获得例外。HLS 分片和重定向也受系统网络规则约束。
- 完整保留地址中的必要查询参数；不要把临时签名当作长期稳定源。地址不能含用户名/密码、片段或空白字符。
- 主备按实际地址数顺序轮换（如 A → B → C → A）；单地址在原线路重试。连接仍遵守最多 4 次自动重试和 2/4/8/16 秒间隔，含首次最多 5 次尝试，并不保证一次失败会试完超过 5 条地址。健康播放超过 60 秒重置重试预算但保留线路位置，下次失败继续下一条；正常播放不定时刷新或切回主线路，URL 参数不用于推导有效期。
- 默认顺序为 KISS、央广 Music Radio，然后按 JSON 顺序排列普通台。已有自定义排序优先，内置台也可自由拖动；“恢复默认顺序”会将两个内置台重新放在最上方。
- 设置里的自定义排序、隐藏和默认电台仍保存在原有偏好中，不写进 JSON；已有排序优先，新 ID 追加。需要按 JSON 新顺序排列时，在设置中使用“恢复默认顺序”。
- 被删除的普通台不再出现在菜单或默认选项中；若上次收听或固定默认指向它，启动时回退到可见电台。空数组仍保留两个内置台，至少一个电台可见。
- 启动时语法、版本、重复 ID 或字段校验失败，App 显示中英文错误提示，本次使用默认列表；用户文件原样保留。运行中手动重新加载失败则继续使用原列表；修复保存后可再次重新加载。不会只加载半份配置，也不会悄悄覆盖错误文件。

界面编辑和手动重新加载共用同一配置文件与校验规则。

## 单 Mac 发布、iPhone 只读（1.2.10 起）

Mac 是唯一配置来源，iPhone 只读取和缓存。共享普通电台资料、稳定 ID、主备地址、全部电台顺序、明确显示选择及默认电台模式；音量、静音、当前播放、上次收听、自动播放、语言、外观、Dock、自启动、更新和运行中的睡眠计时各端独立。“上次收听”使用各端本机记录。内置台的固定播放地址不写入共享普通电台 JSON；内置 ID 及管理规则保持，未更改同步格式。

### 文件与发布

独立“配置同步”页仅保留一张卡片：设置 iCloud 同步、选择／更改文件夹、立即同步、停止同步、简单状态及关联后的打开 iCloud 同步文件夹。本地配置和备份统一从电台配置页打开，不在同步页重复入口。自动设置沿用系统确认的 CloudDocs 标准位置及原生选择器回退；关联仍需确认，已有配置仅可由本机接替，替换前在本机保存一份该发布文件。Mac 不从云端接收电台配置。

数据目录仍为所选目录下的 `RadioBarSync`，直接选择数据目录会规范化到其父目录。“打开 iCloud 同步文件夹”仅在已关联时显示，使用同一授权书签打开实际数据目录，并以系统 isUbiquitousItem 元数据确认属于 iCloud Drive；本地目录或权限异常时提示重新选择 iCloud Drive 目录，不猜测或创建目录，不改现有关联；电台配置页的本地文件夹入口指向 Application Support。书签只存本机，失效不能退回猜测路径；同步目录不得与本机配置目录重叠，拒绝目录及文件符号链接。

唯一输出为 v2 `current.json`：包含配置库 UUID、递增整数序号、Unix 秒时间、电台原始 JSON 的 base64 及共享偏好。完整格式、上限和手机读取规则见 [两端协议](IPHONE_SYNC_SIMPLIFICATION.md)，有效示例见 [station-current-v2.json](examples/station-current-v2.json)。不再生成 UUID 历史快照、版本图或多 Mac 分支，不预留分享／导入框架。

同一配置库的序号先与完整待发布内容一起持久保存，再协调原子替换云端文件。失败重试复用同一发布，重启不将同一序号用于其他内容；发现云端文件与已知回执不同则停止自动覆盖。明确重新关联后可确认以本机接替，序号超过已知回执和现有文件；确认前重新校验目录内容及本机配置。文件协调是合作机制，不能保证跨设备绝对锁定。

配置未变化不重写云端文件。启动、回到前台、成功接受的本机修改及手动操作触发，连续修改合并；编辑／拖动期间延后发布。移除文件夹监听和定时轮询，发布失败在下次触发重试，仍可手动立即同步。外部编辑的本机文件必须先重新加载，不自动上传。

### 本机数据、停止与迁移

Application Support 的原目录、`stations.json`、UserDefaults 键及 bundle ID 保持。发布失败不回滚本机编辑，不阻止离线使用，也不重建播放连接。停止同步保留本机配置、备份、云端文件和私有序号回执，重启不自动重连。

旧版本的 `station-sync-transaction.json` 及已确认但未完成的远端应用先沿原事务恢复，再允许编辑和迁移；异常时保留材料并阻止配置修改。旧关联需重新设置并确认 v2 发布，能可靠恢复时沿用原配置库 UUID；旧关联原始字节归档保留。旧 UUID 云端快照及所有旧备份不批量清理。

手机只读新文件，不扫描旧版历史；未升级 Mac 时继续保留手机缓存并提示在 Mac 更新及发布。新文件下载等待、缺失、损坏或较新格式不能表示清空列表。“配置已发布”仅表示交给本机同步文件夹，不能证明 iCloud 上传完成或 iPhone 已采用。
