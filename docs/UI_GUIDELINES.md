# RadioBar UI 设计规范

本文是 RadioBar 主菜单、设置页面及编辑窗口的共用设计依据。新增页面、在现有页面插入控件、调整提示或图标前，先读本文，再检查相关源码与 Git diff。使用原生 SwiftUI / AppKit 和 SF Symbols，保持素雅、紧凑、可识别。

2.0 沿用当前界面基线：电台标题／计数、排序说明／恢复默认顺序、电台行与添加操作共用圆角卡片；操作标签复用 SettingsActionLabel。菜单栏倒计时使用原生 template 图片和等宽数字；关于页保持居中图标、版本复制、更新控件与离线许可证入口。具体尺寸、间距和状态规范以下文为准，实际验收范围见 TESTING。

用户的新要求优先；未涉及的尺寸、字重、交互和快捷键保持现状。发现现有实现与规范不一致，先记录具体差异，在授权范围内修改，不借新增功能顺手全局改版。

## 1. 总体原则

- 同类操作使用同类样式；不要求所有按钮长得一样，也不以“更现代”为由移除所有按钮背景。
- 图标、文字和点击区域构成一个操作。内部间距小，操作之间的间距大，让用户一眼识别归属。
- 设置使用圆角卡片分组；分隔线用于卡片内部的相关设置行，不用卡片外长横线替代分组。
- 说明紧邻对应控件。优先使用一行短说明；完整规则放 README 或 STATIONS，不在界面堆成长段，也不为容纳规则新增折叠区。
- 用户需要采取行动或理解结果时再提示。普通显示、隐藏、排序不反复弹出规则说明。
- 优先复用现有组件与系统样式，保证浅色、深色、跟随系统及简体、繁体、英文表现一致。

## 2. 按钮选择：按角色和位置区分

文字按钮、图标按钮同样可以是原生控件。下表中的“常规按钮”特指系统提供背景或边框的按钮，不是自行绘制的灰色矩形。

| 操作/位置 | 规定样式 | 使用理由与边界 |
|---|---|---|
| 添加电台 | 常规按钮，左侧 `plus` 与文字组合，列表卡片底部右对齐 | 列表主要入口，与列表共用外框，内部细分隔线区分；不单独悬挂一个加号 |
| 恢复默认顺序 | 次要文字按钮 | 与列表同组，强调程度低于添加；无可恢复内容时使用系统禁用状态 |
| 打开文件、打开文件夹 | 紧凑的图标＋文字按钮，无边框、使用系统强调色 | 辅助入口，共同位于配置文件卡片；图标必须紧贴各自文字 |
| 普通电台行编辑 | 无边框铅笔按钮 | 与对应电台紧邻；不为每一行加入较重的常规按钮；提供完整辅助功能名称和悬停说明 |
| 重新加载、恢复内置电台 | 常规按钮 | 执行配置操作，右对齐于对应标题和说明 |
| 编辑窗口保存 | 系统强调按钮、默认完成操作 | 使用系统默认操作样式与 Return 行为；同一窗口不要让多个按钮争夺默认强调 |
| 编辑窗口取消 | 常规次要按钮 | 与保存相邻，沿用系统位置和 Escape 行为 |
| 删除电台 | 编辑窗口内的 destructive 操作，执行前确认 | 与保存/取消分开，放左侧；不要让删除成为默认操作，或只靠颜色提示风险 |
| 网站、系统设置、帮助入口 | 轻量文字链接，必要时附外跳箭头 | 明确指向外部目的地；不与保存、加载等执行操作混用文案 |
| 菜单内播放、重连、设置、退出 | 现有整行菜单按钮 | 复用 CompactMenuRow，不套用设置页的常规按钮外观 |

不机械地使用“会改变数据就必须有边框”这样的规则。行内编辑、主菜单命令已经有明确位置；保存需要强调，次要入口需要克制。恢复内置列表保留现有备份与反馈流程，本文不额外增加确认步骤；删除继续要求确认。

## 3. 图标、文字与操作分组

### 设置页按钮的尺寸约定

以下是项目约定，单位为逻辑点 pt，不是对系统按钮所有内部尺寸的重绘要求。

| 项目 | 约定 |
|---|---|
| 设置页图标＋文字的内部间距 | 默认 4 pt；显式指定，不依赖 Label 的自动布局 |
| 设置页辅助操作图标 | 通常 12–14 pt，regular；与同组文字视觉居中 |
| 相邻常规按钮 | 默认 8 pt，使用系统 controlSize(.regular) 与系统内边距 |
| 相邻无边框文字操作 | 默认 24 pt；不得与内部 4 pt 混为同一种间距 |
| 列表主要操作与次要文字操作 | 默认 20 pt，独立成组 |
| 操作组与计数/标题 | 用布局分组或至少一个清晰的组间留白；空间不足整组换行 |

明确写出图标文字组合，例如：

```swift
Button(action: addStation) {
    HStack(spacing: 4) {
        Image(systemName: "plus")
        Text(settings.text("添加电台", "Add station"))
    }
    .fixedSize(horizontal: true, vertical: false)
}
.buttonStyle(.bordered)
.controlSize(.regular)
```

此代码是结构示意；生产代码复用 `SettingsActionLabel`，文件入口使用相同的紧凑组合，按钮样式为 `.link`，不在每个页面重复维护间距。

- 不在图标与所属文字之间放 Spacer，不让标签占满整行后再两端对齐。
- 图标和文字属于同一个 Button、同一个辅助功能元素、同一个点击区域；不要只让文字或图标能点击。
- 保持完整按钮标签。英文较长时让操作组移到下一行，不压缩图标、不挤掉标题、不缩小字号来凑空间。
- 预览中给按钮画的背景仅表达层级；实际代码使用系统样式，不硬编码灰色填充、阴影和强调色。

## 4. 主界面：菜单栏与展开菜单

主界面已有较高信息密度，继续沿用原生菜单式布局，不改成设置卡片或大按钮。

| 元素 | 现有基线 |
|---|---|
| 菜单整体 | 宽 256 pt，外侧 padding 5 pt，按内容自然高度布局 |
| 常规菜单行 | 高 24 pt，左右内边距 9 pt，主文字 13 pt regular |
| 菜单行图标 | 15×15 pt 占位，图文间隔 3 pt；播放/暂停、重连、设置、退出的图形为 10 pt regular |
| 当前电台勾选 | 12 pt，保留统一图标占位，不通过加粗名称表达选中 |
| 频率 | 右侧 64 pt 对齐区域，11 pt、弱化颜色、等宽数字；网络台不虚构频率 |
| 快捷键说明 | 右侧 12 pt、次要颜色，沿用现有快捷键 |
| 顶部状态 | 行高 24 pt，7 pt 状态圆点；状态文字 11 pt、中性色 |
| 分组分隔 | 现有 Divider，左右缩进 11 pt，上下留白 4 pt |
| 行悬停 | 整行命中，复用系统选择背景，6 pt 圆角；文字和图标随悬停获得合适对比度 |
| 菜单栏天线 | 18×18 pt template 图标；可选慢动画、默认静态，遵守减少动态效果 |

主菜单背景显式使用原生 `NSVisualEffectView` 的 `.menu` 材质、`.behindWindow` 混合和 `.active` 状态；外观跟随宿主窗口，背景覆盖完整内容且不接收输入。真实通透程度须用桌面上的原生窗口验收，实色背景的离屏预览仅检查布局。

状态文字保持中性，颜色集中在圆点：播放绿、暂停灰、连接/缓冲橙、错误红，具体状态映射复用 `menuStatusTint`。浅色菜单主文字沿用 #252525，深色使用系统 controlTextColor；不要为新增一行另起配色规则。

菜单栏选择“图标和电台名”时，图标与名称间保留现有 en-space 宽度。计时运行时使用原生 template 图片组合天线、名称和时间，由 AppKit 直接以 13 pt 常规字体及等宽数字绘制，避免菜单栏宿主提取文字后丢失字体特性；设置预览复用同一图片。无计时时沿用原生图标与文字。辅助功能名称使用完整电台名称与剩余时间，不含排版填充。

静音、音量滑块与音量图标保持现有独立一行，不补回音量百分比，不把静音替换成暂停。快捷键只有现有空格、⌘R、⌘,、⌘Q，不能因新增功能自动增加全局或数字快捷键。

主菜单以紧凑、稳定的 UI 为优先：顶部只显示简短播放状态，不插入重试详情行，也不保留提示占位。重试、取址、缓冲、失败与播放之间保持相同自然高度；详细失败原因与重试记录在“设置 → 诊断”查看。不要通过固定大高度或强制移动窗口规避背景问题。该问题的排查与实际验收状态见 [HANDOFF](HANDOFF.md)，几何记录与离屏截图不能替代真实菜单合成效果验收。

## 5. 设置页面：布局与卡片

| 元素 | 现有基线 |
|---|---|
| 设置窗口 | 760×620 pt，侧栏宽 176 pt；保留原生窗口按钮、背景拖窗能力 |
| 侧栏 | 顶部预留 56 pt，导航行高 32 pt，分组标题 regular；图标 regular、在 14×14 pt 内等比显示并占用 20×20 pt；左下角从 Bundle 读取版本 |
| 右侧固定标题区 | 高 52 pt，左右 padding 20 pt；图标 18 pt、主标题 13 pt medium、副标题 11 pt；电台配置图标用 list.bullet |
| 内容区 | padding 24 pt，页面纵向分组间隔 14 pt，内容可自然滚动 |
| SettingsCard | 圆角 10 pt，内边距 18 pt，内部默认纵向间隔 16 pt；现有细边框与背景 |
| 背景色 | 侧栏浅/深灰度 0.88/0.16，内容区 0.965/0.12；经 SettingsColors 随原生外观解析，卡片使用系统背景 |
| 设置名称和状态 | 13 pt regular，短说明 12 pt secondary，名称与说明间隔 5 pt |
| 卡片/分组标题 | 13 pt medium；默认电台、计时与诊断卡片标题沿用这一层级 |
| SettingsHint | 11 pt secondary，只承载必要的简短跨控件说明 |
| 普通设置行 | 沿用现有最小高度与间距；通用页单行内容至少 22 pt，带语言说明行至少 42 pt |
| 通用页选择器 | 共用原生 SettingsMenuPicker，宽 196 pt；默认电台选择器沿用整行宽度 |
| 电台行 | 高 38 pt，名称 13 pt regular，序号 11 pt，频率 8 pt，分类 11 pt |
| 折叠区 | 复用 SettingsDisclosureStyle 的 44 pt 整行入口，默认折叠；用于日志/诊断，不用于重新堆放电台规则 |

优先复用 SettingsCard、SettingsRowTitle、SettingsHint、SettingsMenuPicker 和 SettingsDisclosureStyle。不要在同一设置页混用默认 SwiftUI picker 与另一套自行绘制的选择器。

新设置行采用左侧标题/短说明、右侧控件的结构；相关内容放同卡并使用内部 Divider。不同目的的操作使用独立卡片，不在卡片外重复加长分隔线或重复分组标题。侧栏选中使用现有中性背景，不把整行文字和图标染蓝；保留现有导航焦点处理，不扩大为隐藏其它控件的键盘焦点。

电台页的确定结构：

```text
[电台管理圆角卡片：
 电台顺序与显示                        已显示数量
 简短排序说明                        恢复默认顺序
 卡片内部细分隔线
 手柄｜名称与资料｜编辑｜显示开关
 卡片内部细分隔线
 当前列表操作结果（有结果时）          [＋ 添加电台]
]

[配置文件卡片]
 配置文件
 图标+打开文件    图标+打开文件夹
 卡片内部细分隔线
 应用文件中的更改 / 对应说明或结果           [重新加载]

[恢复内置电台卡片]
 标题 / 对应说明或结果                        [恢复]

ⓘ 隐藏的电台不会出现在菜单、默认电台选项或随机选择中，也不会中断当前播放。
```

这是空间关系示意，不是固定列宽或字符对齐方案。中英文根据实际宽度换行。标题区内边距 18 pt、两行间隔 8 pt，与列表之间用内部细分隔线区分。列表尾部操作区水平内边距 18 pt、上下 12 pt，添加按钮右边缘与下方重新加载、恢复按钮一致；能完整同行容纳的短结果位于左侧，否则提示放到按钮上方、间距 10 pt，按钮仍靠右，无结果时不补说明。分隔线沿用列表内部的 18 pt 缩进。文件入口同属一个紧凑操作组；编辑仅属于相应普通台；两个代码内置台没有编辑或删除入口。显示开关与拖动手柄的位置保持现状。

### 配置同步

配置同步页采用一张卡片。具体文案、按钮、确认与反馈规则见本文末尾“配置同步页”，不再提供存储统计、历史、清理或冲突入口。窗口、通用页、电台行、手柄与其他操作布局保持现状。

### 关于页

- 采用用户确认的居中垂直结构，图标维持 88×88 pt、名称 18 pt medium；版本在名称下方，不采用左右布局或将版本推到右边。版本仍可选中，旁边使用无边框复制图标及中英文辅助功能名称、悬停说明，复制成功后勾号反馈约 3 秒。
- 版本下方增加 12 pt secondary 的一句话介绍，保持居中，英文自然换行。“检查更新”与自动检查开关保留原生样式；正常状态移除安装确认说明，仅更新服务启动失败时显示对应错误。
- “访问网站”和“问题反馈”同排居中，使用原有文字链接与右侧外跳箭头。每个标签内部间距 4 pt，两链接间距 24 pt。反馈直接打开 GitHub Issues 列表，完整连接诊断继续在诊断页获取。
- 主卡片底部用内部细分隔线区分“开源许可与致谢”，入口居中、文字与图标使用 secondary；复用现有悬停/按下/焦点反馈，不添加外跳箭头。点击后打开 560×480 pt 原生 sheet，正文可滚动、选择并离线查看完整 Sparkle 许可证及第三方声明；完成按钮和 Escape 可关闭。
- 不增加作者署名、帮助或隐私说明，后续选定后再实现。

### 睡眠定时

- 计时操作与菜单栏显示使用两个独立 SettingsCard，分组间距 14 pt。开始/重新计时使用系统强调按钮，取消为常规次要按钮，间距 8 pt；操作仍集中在设置。
- 分钟输入框 60×30 pt，17 pt regular 等宽数字，单位位于框外；只需容纳 1–720。运行中的剩余时间为 24 pt medium 等宽数字，作为主要状态信息。
- 状态为 13 pt regular、中性色，不使用强调色胶囊；保留 15/30/60/90 分钟预设。标题、短说明与底部 SettingsHint 沿用本页通用层级。
- “在菜单栏显示剩余时间”默认开启且保存选择，只在计时运行时显示；显示卡片内可预览图标、示例电台名称与剩余时间组合，不另增一份名称显示偏好。
- 菜单栏顺序为天线、名称、时间，名称与时间之间用 ` · `。沿用显式 en-space；计时期间长名称截断至 140 pt，完整名称保留在辅助说明。时间使用等宽数字并从分隔符后左对齐，按当前格式的实际宽度绘制，不为不可见的小时位预留左右空白；同一格式内秒数更新保持宽度稳定，跨小时减少显示位数时自然收紧一次。
- 展开菜单固定保留一行定时入口，显示未开启/剩余时间/渐弱停止/已结束，点击进入设置，启停不增删行。6 秒到期淡出过程中不继续显示 00:00 倒计时，不增加闪烁、通知或声音。

## 6. 编辑窗口与操作反馈

编辑窗口沿用原生 sheet。当前宽 480 pt、内边距 24 pt、标题 15 pt medium；表单标签 regular，必填与可选区别用文字说明。字段、错误、操作区保持同一对齐关系；普通界面不暴露内部类型、任务编号或技术诊断日志。

- 底部右侧为取消、保存；删除在左侧并与完成操作分开。用系统键盘和焦点行为，不用整块空白区域充当隐形按钮。
- 校验失败保留窗口和用户输入，在字段/表单附近解释原因及下一步；不能只显示“失败”，也不能把敏感播放地址放进错误日志。
- 文件被外部修改时说明“取消编辑、重新加载后再试”；不要悄悄覆盖或清空草稿。
- 保存期间禁用重复提交和关闭；进行时提示只在耗时足以被感知时显示，短操作直接给最终结果。不要为很短的本地操作增加人工延迟、全屏遮罩或闪烁的转圈。

反馈按用途区分，不把所有信息都做成同一种弹窗：

| 类型 | 位置与持续时间 |
|---|---|
| 列表添加/保存/删除结果 | 紧邻列表操作区域，成功约 5 秒后消失 |
| 配置加载/恢复结果 | 紧邻对应按钮，优先临时替换该操作的短说明；成功约 5 秒、失败约 8 秒后消失 |
| 文件入口失败 | 在文件入口附近显示，不能放到恢复按钮说明里 |
| 编辑表单错误 | 在 sheet 内持续显示，直到修正、重新提交或取消；不套用自动消失计时 |
| 隐藏最后一个显示台 | 保留开关状态并弹出原因，用户确认后关闭；开关保持可点击，不能提前禁用导致无法解释 |
| 隐藏固定默认台 | 在操作后说明启动选择回退；普通显示/隐藏不提示 |
| 删除确认 | 用户确认后执行；取消不改文件、列表或偏好 |

状态文字用中性色；需要区分成功/失败时仅圆点着色，不能整段红绿大字。提示要说明结果与必要的补救步骤，不能依赖颜色、悬停或图标猜测。不要单独新建“规则”常驻卡片或折叠栏；电台使用规则见 [README](../README.md#电台使用规则)，详细配置语义见 [STATIONS](STATIONS.md)。

## 7. 外观、文案与可访问性

- 以窗口 effectiveAppearance 为准，通过现有 radioAppearance 同步 SwiftUI；不要重新引入 preferredColorScheme 与窗口外观相互竞争的实现。嵌套 AppKit/SwiftUI 电台行继续传递 colorScheme 与 controlActiveState。
- 复用 SettingsColors、系统 controlBackgroundColor 和 secondary/tertiary 等语义色。文档中的现有浅色菜单特例不是为所有控件硬编码颜色的许可。
- SF Symbols 统一使用常规字重。新增图标需与同组图形的视觉尺寸、基线和占位对齐；装饰图标不重复朗读，纯图标操作必须提供动作及对象名称。
- 中文使用“电台”，英文使用 Station / Stations；菜单与播放状态使用 menuName，完整名称和频率使用现有模型，不能新建一份容易漂移的简称表。
- 新文案同步中英文，繁体沿用既有转换。不能把英文截断、挤压或只改中文当作完成。
- 无边框操作仍须支持键盘、焦点、禁用和悬停。禁用态由系统处理，不只调低透明度冒充禁用；不全局移除焦点提示。
- 拖动排序使用现有原生 AppKit 源和接收端。新增编辑按钮或透明覆盖层不得截获手柄事件，不得让拖动手柄带动窗口；仅有效 drop 保存，取消不改偏好。

- 复用既有侧栏 `.sync` 路由，标题为“配置同步 / Sync”，在“其他 / Others”分组中排于诊断和关于之前；通用独立，收听分组保持原样。

- 简繁中文及英文、浅深色检查沿用设置预览；“已发布到同步文件夹”不声称手机已收到。具体业务及迁移规则见 STATIONS。
